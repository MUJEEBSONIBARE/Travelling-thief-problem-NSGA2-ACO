# Travelling Thief Problem Solver — NSGA-II + ACO

A Python implementation of a multi-objective **Travelling Thief Problem (TTP)** solver combining **Non-dominated Sorting Genetic Algorithm II (NSGA-II)** with **Ant Colony Optimization (ACO)** for route construction and a profit-to-weight-ratio heuristic for knapsack selection.

The project was developed as part of a Nature-Inspired Computation group project and investigates how different nature-inspired optimisation approaches can address the interdependent routing and item-selection decisions in the TTP.

---

## Overview

The **Travelling Thief Problem (TTP)** combines two optimisation problems:

- **Travelling Salesman Problem (TSP):** determine an efficient route visiting all cities.
- **0–1 Knapsack Problem:** select items to maximise profit while respecting the thief's carrying capacity.

The two components are interdependent because the weight of selected items affects travelling speed and therefore total travel time.

This implementation uses a **bi-objective formulation**:

1. **Maximise total profit**
2. **Minimise total travel time**

Rather than combining the objectives into a single renting-ratio fitness measure, the project evaluates profit and travel time separately and uses NSGA-II to identify non-dominated solutions.

---

## Key Features

- **bTTP dataset parsing** for problem instances.
- **ACO-based TSP route construction** using pheromone information and distance-based heuristics.
- **Profit-to-weight-ratio knapsack heuristic** for generating item-selection plans.
- **NSGA-II multi-objective optimisation** using non-dominated sorting and crowding distance.
- **Genetic operators** including order crossover, single-point crossover and bit-flip mutation.
- **Parallel data processing** to improve computational efficiency.
- **Memory-mapped distance matrices** using NumPy `np.memmap`.
- **Float16 pheromone matrices** to reduce memory requirements for very large instances.
- **Distance-matrix optimisation** using route symmetry and upper-triangular calculations.
- Experiments across small, medium and large TTP benchmark instances.

## Technical Approach

### 1. Initial Population

The initial population combines solutions generated by separate heuristics:

**ACO TSP solver**

ACO constructs candidate routes using pheromone information and a distance heuristic. The main parameters include:

- `ALPHA = 1`
- `BETA = 5`
- Evaporation rate = `0.3`
- Pheromone deposit = `100`

**Knapsack heuristic**

Items are prioritised using their profit-to-weight ratio. A random capacity is generated for each parent solution to encourage diversity in the initial population while respecting the problem's capacity constraint.

### 2. NSGA-II

NSGA-II evolves the combined route and picking-plan representations.

The optimisation process uses:

- Non-dominated sorting
- Crowding distance
- Elitist selection
- Tournament selection
- Crossover
- Mutation

The route is represented as a permutation of cities, while the picking plan is represented as a binary array indicating whether each item is selected.

### 3. Objective Evaluation

The algorithm evaluates:

- **Profit:** total profit from selected items.
- **Travel time:** total time required to complete the route, taking the weight of selected items into account.

The project therefore searches for solutions that provide different trade-offs between profit and travel time rather than a single optimum.

## Computational Optimisation

Large TTP instances, particularly the PLA datasets, required substantial memory and computational resources.

Several optimisation techniques were implemented to make the problem computationally manageable.

### Memory-Mapped Distance Matrix

A large distance matrix was stored on disk and accessed using NumPy `np.memmap`, allowing portions of the matrix to be loaded when required instead of keeping the complete matrix in RAM.

This approach was particularly important for the large PLA instances.

### Reduced-Precision Pheromone Matrix

For large instances, the pheromone matrix was stored using `float16` precision to reduce memory requirements.

### Distance-Matrix Symmetry

Because distances between two locations are symmetric, redundant calculations were reduced by calculating the upper portion of the distance matrix and using symmetry to populate the corresponding lower portion.

### Parallel Processing

Parallel processing was also introduced to reduce the computational cost of data processing and route evaluation.

These techniques were important for enabling experiments on the larger benchmark instances.

## Experimental Evaluation

The project compared several nature-inspired approaches to the TTP, including:

- NSGA-II
- Ant Colony Optimization (ACO)
- Particle Swarm Optimization (PSO)
- Genetic Algorithm (GA)
- MA2B
- Memetic Algorithm with Tabu Search (MATL/MATLS)

The group used a consistent evaluation framework based on objective functions, fitness-evaluation limits, solution filtering and benchmark instances.

### Fitness Evaluation Limits

Different limits were used according to the size of the benchmark instances:

| Instance group | Fitness evaluations |
|---|---:|
| a280 | 200,000 |
| fnl4461 | 50,000 |
| pla33810 | 2,600 |

Time-based stopping criteria were avoided because the algorithms were executed on different hardware.

---

## Results

The group evaluation reported the following normalised hypervolume values for the **a280-n2790** instance:

| Algorithm | Normalised Hypervolume |
|---|---:|
| NSGA-II | 0.9900 |
| PSO | 0.9795 |
| ACO | 0.9167 |
| Genetic Algorithm | 0.8650 |
| MA2B | 0.6155 |
| MATL | 0.5283 |

The results reported in the project showed strong Pareto-front coverage for the NSGA-II approach.

The final approach investigated in this repository combines **NSGA-II + ACO + a profit-to-weight-ratio knapsack heuristic**.

## Running the Project

### 1. Clone the repository

```bash
git clone https://github.com/MUJEEBSONIBARE/Travelling-thief-problem-NSGA2-ACO.git
cd Travelling-thief-problem-NSGA2-ACO
```

### 2. Prepare the dataset

Place the required bTTP benchmark dataset in the `Datasets/` directory.

For large-scale experiments, make the required distance-matrix file available in the `Mapped_distance_matrix/` directory or in the location expected by the relevant script.

### 3. Install dependencies

```bash
pip install numpy
```

### 4. Run the relevant implementation

The repository contains implementations for different benchmark instances in the `Notebooks and scripts/` directory.

Run the appropriate Python script for the benchmark instance being investigated.

For example:

```bash
python "Notebooks and scripts/pla33810-n33809.py"
```

The exact dataset and script should be matched to the corresponding benchmark instance.
